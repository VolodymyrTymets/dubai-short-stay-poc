Approved-by: volodymyr · 2026-09-16

Pattern followed:
- Backend: `api/src/property/property.resolver.ts` + `property.service.ts`'s existing `properties` public
  query (`findAllProperties`) — same `status: LIVE, deleted: false` visibility rule, same bare `@Query` (no
  guard) convention, singular instead of paginated.
- Frontend: `web/packages/guest/src/pages/SearchResultsPage.tsx` / `HomePage.tsx` from `guest-home-search`
  — same shared-query-hook + loading/error/empty/success states, same `mapPropertyToCard`-style mapper
  pattern, same routed-page-under-`Layout` shape (`router.tsx`).

## Contract changes
- boundary: additive GraphQL query `propertyBySlug(slug: String!): PropertyEntity` (nullable), public, no
  new type — reuses `PropertyEntity`/`PROPERTY_INCLUDE`. No existing field or query changes.
- data: none — no schema/migration change, read-only query against existing `Property` columns.
- generated output: `api/schema.gql` regenerates on `api/` dev-server restart;
  `web/shared/api/generated.graphql.tsx` + `web/introspection.json` regenerate via `(cd web && yarn
  codegen)` once the new query is live — both are consumed in this same PR (rule S4).

## Requirements (ordered, each independently verifiable)

### R1 — `propertyBySlug` public query (S)
- files:
  - `api/src/property/property.service.ts` (change: add `findPublicPropertyBySlug(slug)`, sibling to
    `findAllProperties`/`findPropertyForOwner`)
  - `api/src/property/property.resolver.ts` (change: add the `propertyBySlug` query, no guard, matching
    the `properties` query's comment/convention)
  - `api/test/property/property.e2e-spec.ts` (change: add a real-transport GraphQL test, following
    `api/test/auth/sign-in.e2e-spec.ts`'s `INestApplication` + `supertest` `/graphql` POST pattern rather
    than this file's existing Prisma-only style — backend-core.md rule 22 requires the real transport)
- layer: resolver → service → Prisma (no new layer)
- test: `property.e2e-spec.ts` — asserts (a) a `LIVE` property is returned by its slug with the expected
  fields, (b) a `DRAFT` property's slug returns `null`, (c) an unknown slug returns `null` — no auth header
  sent in any case
- executed how: `(cd api && yarn start:dev)` (real DB), then a real `curl`/GraphQL POST to
  `propertyBySlug(slug: "…")` against a seeded dev property (`prisma-migrate` seed data already has 100
  properties) captured in the PR evidence block
- risk: none — additive, read-only, same visibility filter already proven by `findAllProperties`

### R2 — `PropertyDetailPage` (M)
- files:
  - `web/shared/api/property/query.ts` (change: add `PROPERTY_BY_SLUG_QUERY` gql operation next to the
    existing `PROPERTIES_QUERY`)
  - `web/packages/guest/src/pages/PropertyDetailPage.tsx` (new)
  - `web/packages/guest/src/router.tsx` (change: add `{ path: 'property/:slug', Component:
    PropertyDetailPage }`)
  - `web/shared/api/generated.graphql.tsx`, `web/introspection.json` (regenerated by `yarn codegen`, not
    hand-edited)
- layer: page component → generated `usePropertyBySlugQuery` hook (Apollo) — no new shared component
  extracted yet (frontend-react.md rule 9 — this is the first and only consumer)
- test: none at the unit level (`web/` has no test runner yet, per `CLAUDE.md`'s command map) — verified by
  the execute step below, per `web-page-layout`/`guest-home-search` precedent
- executed how: `yarn dev:guest` (`web/`) with the API dev server running; open `/property/<real seeded
  slug>` and screenshot success; open `/property/does-not-exist` and screenshot the not-found empty state;
  screenshot the loading skeleton (throttle network) and simulate an error (stop the API) for the retry
  state — all four states captured for the PR evidence block
- risk: the design's gallery/booking-card layout is desktop-fixed-width (1440px canvas) — this repo's
  existing pages (`HomePage`, `SearchResultsPage`) are similarly desktop-first with no mobile breakpoints
  yet, so this matches, not regresses

### R3 — Wire card navigation (S)
- files:
  - `web/shared/components/PropertyCard.tsx` (change: add a required `href: string` prop; render a
    "stretched link" — an absolutely-positioned `<Link to={href}>` covering the card as the first child —
    so the whole card is a real, keyboard-reachable link without nesting the existing favorite `<button>`
    inside an `<a>`, which is invalid HTML)
  - `web/shared/api/property/mapPropertyToCard.ts` (change: return `href: `/property/${property.slug}``)
  - `web/packages/guest/src/showcase/CardsSection.tsx` (change: pass a placeholder `href` to its two
    hand-written `PropertyCard` usages — the dev-only `/dev/components` preview, not a real consumer, but
    it would otherwise fail to build once `href` is required)
- layer: shared component (used by both `HomePage` and `SearchResultsPage` via `PropertyResultsGrid` — one
  change covers both, per AC4)
- test: none (same as R2 — no web test runner yet)
- executed how: from `HomePage` and from `SearchResultsPage`, click a card and confirm the URL changes to
  `/property/<slug>` with no full page reload (Network tab shows no document request) and the favorite
  heart button still toggles without navigating — captured as a short screen recording or two
  before/after screenshots per page in the PR evidence block
- risk: none — additive prop, only call site is `PropertyResultsGrid`

## Risks
| Risk | Impact | Cheapest way to find out early |
|------|--------|-------------------------------|
| Amenity/accessibility labels and host name stay unavailable, so two mockup sections read as generic/placeholder text | Page looks visibly incomplete next to the mockup | Flagged explicitly in spec.md + PR body as a follow-up ticket, not hidden |

## Assumptions
- `slug` (not `id`) is the route/query param — see spec.md's Open question 1.
- The new query is named `propertyBySlug` since `property` is already taken by the owner-scoped query —
  Open question 2.
- Amenity/accessibility catalog labels and host display name are deferred to a follow-up ticket rather
  than built here — Open question 3.
